# Decisions

Choices made where the plan was unclear or silent (PLAN section 0.4). Newest at the bottom.

| Date | Question | Decision | Reason |
|---|---|---|---|
| 2026-11-19 | The plan file was `docs/GYM_APP_PLAN.md`, but the plan and CLAUDE.md refer to `docs/PLAN.md`. | Renamed it to `docs/PLAN.md`. | The plan header says "Save this file as: docs/PLAN.md". |
| 2026-11-19 | D0 says to move "the existing Flutter project" into `mobile/`, but the repo had none and none was found on the machine. | Created a new project with `flutter create --org com.example --project-name gym_app --platforms android,ios mobile`. | Simplest option. Only Android and iOS are targets. The `com.example` id is tracked in OPEN_QUESTIONS #7. If an existing project turns up, its `lib/` can replace this one before D4. |
| 2026-11-19 | Host port for Postgres. | Host port **5433** by default (`POSTGRES_PORT` in root `.env`); the container still uses 5432. | Port 5432 was already used on the dev machine, and a local Postgres often holds it. |
| 2026-11-19 | Where does the e2e test database (`DATABASE_URL_TEST`, PLAN section 11) live? | Same container, second database `gym_test`, created by `docker/postgres/init/01-create-test-db.sh` on first start. | No extra container. Suites can reset it freely. |
| 2026-11-19 | pgAdmin is "optional". | It is in compose under the `tools` profile: `docker compose up -d` starts only Postgres, and `--profile tools` adds pgAdmin. | Keeps the default start fast; pgAdmin is available on demand. |
| 2026-11-19 | D0 asks for Prettier + ESLint in the backend, but the NestJS app is created only in D1 (`nest new`). | D0 adds `backend/package.json` (lint/format scripts only), `.prettierrc`, `eslint.config.mjs` (same shape as the Nest CLI's flat config) and a strict `tsconfig.json`. In D1, generate the Nest app (e.g. `nest new` in a temp folder with `--skip-git`) and merge its files into `backend/`, keeping these configs. | Satisfies D0 without creating the D1 scaffold early. |
| 2026-11-19 | What does "strict" mean for `flutter_lints`? | `flutter_lints` + analyzer `strict-casts`, `strict-inference`, `strict-raw-types` + extra rules (see `mobile/analysis_options.yaml`). Generated files (`*.g.dart`, `*.freezed.dart`) are excluded. | Common strict baseline that still works with code generation. |
| 2026-11-19 | Line endings on Windows. | `.gitattributes` normalizes to LF (CRLF only for `.bat/.cmd/.ps1`); `.editorconfig` and Prettier use LF. | Prevents CRLF churn and Prettier `endOfLine` errors across OSes. |
| 2026-11-19 | Which Prisma version? npm's `latest` tag is a release candidate (8.0.0-rc), and Prisma 7 no longer accepts `url = env(...)` in `schema.prisma`. | **Prisma 6.19.3**, pinned exactly (`prisma` + `@prisma/client`). | It is the newest stable line that accepts the PLAN section 6 schema exactly as written. Upgrading later is a separate, deliberate task. |
| 2026-11-19 | Which NestJS version? The Nest 12 CLI generates ESM + Vitest + oxlint. | **NestJS 11** (CommonJS, Jest, ESLint), scaffolded with `@nestjs/cli@11` in a temp folder and merged into `backend/` (as planned in D0). | Matches PLAN 5.2 (Jest, supertest) and the D0 ESLint setup, and avoids ESM friction with Prisma 6. |
| 2026-11-19 | `User` in PLAN section 6 has relations to training/premium models that D1 does not create. | The D1 migration contains only the core models. `User.assignment`, `sessions`, `measurements`, `notesReceived`, `notesWritten` and `ownedPlans` are added with their models in D11/D13. | Prisma cannot declare relations to models that do not exist. PLAN D1 asks for the core models only. |
| 2026-11-19 | Representation of `@db.Date` values in code. | A "local date" is a JS `Date` at 00:00 UTC of that calendar day (what Prisma reads/writes for `DATE`). `gym-date.ts` does all arithmetic in UTC (`date-fns` `addMonths` on `@date-fns/utc` `UTCDate`), and `date-fns-tz` turns an instant into the gym-local date. | Results never depend on the server's timezone, and values round-trip with Prisma without conversion. |
| 2026-11-19 | Where does "today" come from? | `ClockService.now()` is the only `new Date()` for business logic. `ClockService.today()` = `todayLocal(now, GYM_TIMEZONE)`. Tests use `FixedClockService`. | PLAN sections 6 and 11. The timezone comes from the `GYM_TIMEZONE` env var (the glossary says it is configured there). `GymSettings.timezone` is only seeded from it. |
| 2026-11-19 | `PUSH_ENABLED` default. | `.env.example` and the config default use `false`; `FIREBASE_SERVICE_ACCOUNT_JSON` is required only when it is `true`. | Push is implemented in D8. Until then, `true` would require Firebase credentials that do not exist yet. |
| 2026-11-19 | Extra environment variables not listed in PLAN section 10. | Added `NODE_ENV`, `DATABASE_URL_TEST` (PLAN section 11), `LOG_LEVEL`, `SEED_ADMIN_FIRST_NAME`, `SEED_ADMIN_LAST_NAME` (default "Admin" / "Gym"). | The seed needs a name for the admin (`User.firstName/lastName` are required). The others are standard operational settings. |
| 2026-11-19 | Seed behaviour on re-runs. | Idempotent: `GymSettings` and `TierPrice` are created only if missing (owner-edited prices are never overwritten). The admin is created only if the phone does not exist, with `mustChangePassword = true`. `SEED_ADMIN_PHONE` must already be normalized (`+` and digits); phone normalization arrives in D2. | Safe to run in any environment. |
| 2026-11-19 | Global rate limit. | `@nestjs/throttler`: 120 requests/min per client on every route, except `/health`. | PLAN D1 asks for a throttler but sets only the login/check-in limits (D2/D6). 120/min does not get in the way of normal app use. |
| 2026-11-19 | Helmet on plain HTTP in development. | HSTS and the CSP `upgrade-insecure-requests` directive are enabled only when `NODE_ENV=production`. | On `http://localhost` they would stick in the browser and break Swagger UI's assets. Production runs behind HTTPS (PLAN section 10). |
| 2026-11-19 | Health endpoint when the database is down. | `GET /api/v1/health` returns `503 {status:"error", db:"error"}` (same shape as the success response, not the error format). | Monitoring tools expect a stable body from health endpoints. |
| 2026-11-19 | How e2e tests reset the test database. | `test/support/global-setup.ts` runs `prisma migrate deploy` on `DATABASE_URL_TEST` and then TRUNCATEs every table. `resetDatabase()` is available for suites, and refuses to run unless `DATABASE_URL` is the test URL. | Equivalent to a reset but non-interactive and fast. The guard prevents wiping the dev database by mistake. |
| 2026-11-19 | [R-45] needs a way to deactivate an admin, but section 8.2 only defines deactivate for `/admin/members/:id`. | Added `POST /admin/staff/:id/deactivate` and `/reactivate` (ADMIN only, staff roles only; a member id returns 404). The shared `UsersService.deactivate` applies [R-43] (revoke tokens) and [R-45] (row-locked check of the remaining active admins). | Without it, [R-45] could never trigger and a fired trainer or a lost kiosk could not be locked out. |
| 2026-11-19 | Access token checks. | `JwtStrategy` reloads the user on every request: inactive or deleted → 401, and `mustChangePassword` is read live. Claims are `{sub, role, typ:"access"}`, HS256. | Deactivation [R-43] and finishing the password change take effect immediately, not after up to 15 min. The cost is one primary-key lookup per request. |
| 2026-11-19 | Refresh token format and storage. | 256-bit random value (base64url), stored as SHA-256 (`tokenHash`). Rotation is a conditional update in a transaction, so two concurrent refreshes with the same token count as reuse. Reuse → every token of the user is revoked → 401 `INVALID_REFRESH_TOKEN`. | High-entropy tokens need no slow hash, and lookup by hash stays a unique-index query. Matches section 10 (rotation with reuse detection). |
| 2026-11-19 | Login error details. | Unknown phone and wrong password both → 401 `INVALID_CREDENTIALS` (with a dummy argon2 verify for unknown phones). An inactive account → 403 `ACCOUNT_INACTIVE`, but only when the password is right. | Matches the login screen's three errors (section 9.1) without letting anyone probe which phones exist. |
| 2026-11-19 | Change password extra rules. | A wrong current password → 400 `WRONG_CURRENT_PASSWORD`. A new password equal to the current one → 400 `PASSWORD_UNCHANGED`. Other sessions are not revoked. | The forced change after a temporary password [R-41] must actually change it. Revoking other sessions was not asked for. |
| 2026-11-19 | Default country code for phone normalization. | DTOs normalize with `+591` (`DEFAULT_COUNTRY_CODE`). `GymSettings.defaultCountryCode` is not read yet. | Validation runs before any service code, so it cannot query settings. If the gym ever needs another default, read it from settings at that point. |
| 2026-11-19 | Temporary password alphabet. | Excludes `0 O 1 l I` as [R-41] says, and also `o`. Always contains an uppercase letter, a lowercase letter and a digit. | `o` is as ambiguous as `0` when read aloud or from a screenshot. |
| 2026-11-19 | Lists of staff. | `GET /admin/staff` is paginated (section 8 conventions), hides inactive accounts unless `includeInactive=true`, and filters by `role`. | Same default as [R-43] for members. |
| 2026-11-19 | ESLint `no-unsafe-member-access` / `no-unsafe-assignment` in tests. | Turned off for `test/**` and `*.spec.ts` only. | supertest types `res.body` as `any`; production code keeps the full type-checked rules. |
| 2026-11-19 | [R-09]: when an active member renews with a different tier, the tier applies from the new period, but `Membership` has a single `tier` column. | Added `Membership.nextTier` and `Membership.nextTierStartDate` (nullable; migration `membership_next_tier`). The switch is applied (with a `TierChange` row) whenever the membership is read or written, and before member lists. D8's daily job will call `applyAllDueScheduledTiers()` too. | Smallest additive change that represents a future tier. It touches neither money nor the payment history and can be dropped later. |
| 2026-11-19 | Does voiding a payment revert a tier change? | No. A void recalculates dates [R-12] and the *scheduled* tier, but does not revert a tier that already applied. The admin corrects the tier with a tier change. | [R-12] only defines the date recalculation. Automatically reverting tiers could unassign trainers [R-16] by surprise. |
| 2026-11-19 | Voiding the only remaining period payment. | Allowed. The membership keeps its `startDate` and gets `endDate = startDate − 1` (expired, 0 days left). | The membership row must keep dates (NOT NULL), and "no paid days" means expired. |
| 2026-11-19 | Upgrade with a waived charge. Section 8.3 says "payment `kind=UPGRADE` if amount > 0", while [R-13] says "or sets it to 0 with a note". | An UPGRADE payment (months 0) is recorded whenever the suggestion or the amount is > 0, so a waived charge is stored as amount 0 with its required note (method defaults to `OTHER`). A charged upgrade needs a method (400 `PAYMENT_METHOD_REQUIRED`). | Without a record, the [R-13] note would have nowhere to live and the discount would not be auditable. |
| 2026-11-19 | Tier change on an expired membership; same tier; downgrade with an amount. | Expired → 409 `MEMBERSHIP_EXPIRED` (use a renewal, which changes tier immediately [R-09]). Same tier → 400 `TIER_UNCHANGED`. Downgrade with amount > 0 → 400 `DOWNGRADE_HAS_NO_CHARGE`. | [R-13]/[R-14] talk about changes during an active period. A downgrade has no charge [R-14]. |
| 2026-11-19 | [R-13] rounding. | `round()` is half-up to whole currency units (Bs). | A plain `round` in the rule; whole bolivianos are what reception charges. |
| 2026-11-19 | Money in the API. | Inputs are JSON numbers with at most 2 decimals; outputs are strings with 2 decimals (`"150.00"`). Calculations use Prisma `Decimal`. | Section 10: money never uses floats. Strings keep exact values in JSON. |
| 2026-11-19 | New member preview. | Added `GET /admin/members/preview?tier&months&startDate` (period + suggested amount). | Section 9.3 #3 says the new-member stepper shows the "suggested amount (from preview)", but section 8 only defines a preview for existing members. |
| 2026-11-19 | Member status filters. | `active` = account active and `endDate ≥ today`. `expiring` = active with 1..N days left (`expiringWithinDays`, default 7). `expired` = account active and `endDate < today`. `inactive` = account deactivated. No `status` → inactive accounts hidden [R-43]. | Definitions follow [R-01]–[R-03]. 7 days matches the first reminder [R-24]. |
| 2026-11-19 | `GymSettings.timezone` vs `GYM_TIMEZONE`. | `PUT /admin/settings` cannot change the timezone (400 if sent). `GET` returns the effective env value. | The glossary makes the timezone an env setting, and changing it at runtime would shift every date computation. |
| 2026-11-19 | `GET /admin/payments` totals and voided rows. | Items include voided payments by default (`includeVoided=false` hides them). `totals` always counts only non-voided payments that match the filters. `from`/`to` are gym-local dates of `paidAt` (inclusive). | Reception sees corrections in the list while revenue stays correct. |
| 2026-11-19 | Concurrency on payments. | Renewals, voids and tier changes lock the membership row (`SELECT … FOR UPDATE`) inside their transaction. | Two simultaneous renewals must not both start from the same `endDate`. |
| 2026-11-19 | Renewing a deactivated member. | Allowed. | Not forbidden by the plan. The admin may renew before reactivating. |
| 2026-11-19 | Flutter 3.50 deprecates `package:flutter/material.dart`. | The app imports `package:material_ui/material_ui.dart` (and its `GlobalMaterialLocalizations.delegates`). | The new official package; go_router 18 already uses it. Avoids deprecation warnings in `flutter analyze`. |
| 2026-11-19 | D4 says "add dependencies (5.3)", but some need native setup (Firebase, camera, sockets). | D4 adds the foundation libraries (riverpod + generator, go_router, dio, flutter_secure_storage, freezed, json_serializable, build_runner, intl, flutter_localizations, mocktail). `qr_flutter`, `mobile_scanner`, `permission_handler`, `socket_io_client`, Firebase, `flutter_local_notifications`, `fl_chart`, `wakelock_plus`, `share_plus` are added by the deliverable that uses them (D5, D7, D8, D9, D12). | Unused plugins with native config (e.g. Firebase without `google-services.json`) could break the build, and the app must stay runnable. |
| 2026-11-19 | Generated code (`*.g.dart`, `*.freezed.dart`, `lib/l10n/generated/`). | Committed. | A fresh clone passes `flutter analyze` and runs without a build_runner step. Regenerate after changing annotated classes or `.arb` files (README). |
| 2026-11-19 | Environments for `API_BASE_URL`. | `--dart-define-from-file=config/{dev,staging,prod}.json` (`APP_ENV`, `API_BASE_URL`), plus matching VS Code launch configurations. Staging/prod URLs are `example.invalid` placeholders. Without defines the app uses dev (`http://10.0.2.2:3000`). | No Android product flavors yet: those need the final application ID (OPEN_QUESTIONS #7). Servers do not exist until D10/D14. |
| 2026-11-19 | Plain HTTP to the dev backend. | `usesCleartextTraffic="true"` only in the debug manifest; release builds stay HTTPS-only. | Section 10: HTTPS only in production. |
| 2026-11-19 | "Log out on failure" of the token refresh. | Logs out only when the server rejects the refresh token (4xx). A network/5xx failure during the refresh keeps the session and just fails the request. At launch, an offline `/me` shows the splash error with Retry and keeps the tokens. | Being offline (or a kiosk losing Wi-Fi) must not sign the user out. |
| 2026-11-19 | Forced password change form. | Asks for the current (temporary) password too. | `POST /auth/change-password` requires `currentPassword`; keeping the login password in memory would be worse. |
| 2026-11-19 | Login country code. | A prefix selector with +591 first and a short list of nearby countries; the phone is normalized on the device with the same rules as the backend [R-40] and sent normalized. | Section 9.1 #2. An input that starts with `+` or `00` ignores the selector, as on the server. |
| 2026-11-19 | App name and brand color. | Placeholder name "Gym"/"Gimnasio" and seed color `#D9480F`. | Not specified; trivial to change in `app_*.arb` / `AppTheme.brandColor`. |
| 2026-11-19 | Role homes in D4. | Simple placeholders (greeting, role, logout; members also see tier badge, days left and end date from `/me`). Bottom navigation comes with the screens it links to (D5+). | D4 asks for "placeholder home screens per role". |
